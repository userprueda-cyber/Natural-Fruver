# Natural Fruver — online catalog

Mobile-first product catalog for **Natural Fruver Pereira**. Customers browse, search and build an order that is sent to the store over WhatsApp. Workers manage products and orders from their phones. It costs nothing to run: Google Sheets + Apps Script + GitHub Pages.

> 🇨🇴 The step-by-step setup and daily-use guide for the store is in Spanish: **[docs/GUIA.md](docs/GUIA.md)**.

```
 Customers ──► site/index.html  ──GET catalog──►  Apps Script web app  ◄──► Google Sheet
 (phones)      (GitHub Pages)   ──POST order──►   (apps-script/*.gs)        Productos · Pedidos ·
                    │                                    ▲                   Categorias · Config ·
                    └──► wa.me link with order text      │                   Trabajadores
 Workers  ──► site/admin.html  ──POST admin_* + PIN──────┘
```

## How it works

- **The Google Sheet is the database.** The owner can always open it and edit it by hand; manual edits reach the site within a few minutes (the cache is cleared on edit and expires after 5 min).
- **Ordering reserves stock.** When a customer taps *Enviar pedido por WhatsApp*, the site first POSTs the cart to Apps Script. Under a script lock it re-checks availability, prices the order from the sheet (client prices are ignored), subtracts stock, writes a `Pedidos` row with a number like `NF-0042`, and only then opens WhatsApp with the order text. If an item sold out in the meantime, the customer sees exactly what changed.
- **Cancelling returns stock.** Workers confirm → deliver or cancel orders. Cancelling puts tracked stock back. Orders left *pendiente* for `horas_cancelar_pendientes` hours (default 3) are cancelled automatically, so fake or abandoned orders don't lock up stock.
- **Stock is optional per product.** An empty `stock` cell means "not counted" (only the *disponible* switch matters). A number means it's decremented per order. `kg`/`lb` products sell in 0.5 steps.
- **Offers expire on their own.** `precio_oferta` + optional `oferta_hasta` date.
- **Workers log in with a PIN**, not a Google account (tab `Trabajadores`). Every change records who made it. Ten wrong PINs lock the admin for 10 minutes.
- **Scheduled jobs** (Apps Script triggers): refresh the catalog cache every 15 min, cancel stale orders hourly, and an optional daily 6 am email summary of yesterday's orders and low stock.

## Layout

| Path | What |
|---|---|
| `apps-script/` | Backend: `Api.gs` (doGet/doPost router), `Catalog.gs`, `Orders.gs`, `Admin.gs`, `Jobs.gs` (menu + triggers), `Setup.gs` (creates tabs, sample data, admin PIN), `Util.gs`, `appsscript.json` |
| `site/` | Static site. `index.html` + `js/app.js` for customers, `admin.html` + `js/admin.js` for workers, `js/shared.js` (search, formatting, opening hours, WhatsApp message), `js/config.js` (**set `API_URL` here**) |
| `site/img/` | Logo and icons (`logo.png`, `icon.png`, `og.jpg`) and one 400×400 photo per product in `productos/<id>.jpg`, cropped from the store's Instagram catálogo |
| `site/data/demo-catalogo.json` | Sample catalog used when `API_URL` is empty (demo mode); generated by `npm run demo` from `Setup.gs` |
| `tests/` | `node --test` suites. `gas-mock.js` runs the real `.gs` files against in-memory Sheets/Cache/Lock/Drive mocks |
| `.github/workflows/site.yml` | Runs tests on every push; deploys `site/` to GitHub Pages from `main` |

## Development

```bash
npm test          # backend (via mocks) + shared site logic
npm run demo      # regenerate the demo catalog after changing Setup.gs sample data
npm run serve     # http://localhost:5173 — demo mode if API_URL is empty
```

In demo mode both pages are fully clickable. The admin accepts any 4-digit PIN and nothing is saved.

## Deploying

1. Follow **[docs/GUIA.md](docs/GUIA.md)** §1 to create the Sheet, paste the Apps Script, run *Configurar hojas*, and deploy the web app (execute as *me*, access *anyone*).
2. Put the `/exec` URL in `site/js/config.js`.
3. In GitHub: **Settings → Pages → Source: GitHub Actions**, then merge to `main`. The site will be at `https://<user>.github.io/<repo>/` and the admin at `…/admin.html`.

Optional: use [`clasp`](https://github.com/google/clasp) to push `apps-script/` instead of copy-pasting (`clasp clone <scriptId> --rootDir apps-script`, then `clasp push`). After changing backend code, publish a **new version of the same deployment** (Deploy → Manage deployments → Edit → New version) so the URL doesn't change.

## Known limits / next steps

- **Real product data** still has to be loaded. Instagram couldn't be reached from the build environment. Fill the `Productos` tab directly (it accepts a paste from a spreadsheet), or pull the data from Instagram in a local session.
- WhatsApp confirmation relies on the customer actually sending the message. Unsent orders are auto-cancelled after N hours. Full automation would need the paid WhatsApp Business API.
- Apps Script quotas (about 30 simultaneous executions, 6 min/run) are far above a single store's traffic, and the catalog is served from cache.
- The PIN lockout is global, so someone guessing PINs can lock workers out for 10 minutes. If that becomes a problem, move the admin to Google sign-in.
